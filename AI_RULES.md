## Рабочие правила

- Менять только то, о чём попросил владелец; не переписывать технические объяснения без запроса.
- Проверять факты о браузере, Event Loop, React и Next.js; не использовать неточные упрощения и детские аналогии.
- Сохранять содержание и работающие интерактивные примеры при визуальных правках.
- Перед изменением просматривать текущую версию файлов, чтобы не перезаписать чужие коммиты.
- После правок проверять навигацию, FAQ, адаптивность и поведение скриптов.
- Не публиковать и не пушить по умолчанию при локальной работе. При работе через подключённый GitHub сохранять изменения только по запросу пользователя.
- Отвечать на русском, кратко, с технической терминологией.

## О проекте

- Статическая документация Tech Notes на GitHub Pages.
- Основной сайт: `index.html`.
- Вопросы оформляются как FAQ с закрытыми ответами по умолчанию.

## Универсальный формат FAQ

- На каждой странице документации используется **один отдельный блок «Вопросы и ответы»** в конце темы.
- Скрипт `assembleFaqForPage(page)` в `index.html` автоматически собирает вопросы в этот блок.
- Чтобы добавить одиночный вопрос, создай `<section id="unique-id"><h2>Вопрос?</h2>...ответ...</section>` в нужной теме: скрипт превратит его в закрытый `<details class="faq-item">`.
- Для подборки вопросов используй `<section id="topic-qa"><h2>Название категории</h2><details class="faq-item"><summary>Вопрос?</summary><div class="faq-answer">Ответ.</div></details></section>`.
- В длинной статье прямой `<h3>` с вопросительным знаком тоже переносится в FAQ вместе с ответом до следующего заголовка.
- Не дублируй ответы одновременно в основной статье и FAQ. Сохраняй уникальные `id` и ссылки из оглавления.
- Не добавляй атрибут `open` к `details`: ответ должен быть скрыт при первом открытии страницы.
- Темы открываются отдельными страницами, ссылки на разделы — через URL-якоря.
